The courtyard model remains prominent at 1440×900. Roof selection and a protected facade are explicit, not hidden demo facts. Instructions and inventory share local model state; the brief and editor image/calibration context remain associated with the same project slot. Local browser saves and complete backups retain this content across reload or restoration. Undo histories and camera positions start fresh; legacy scene imports contain geometry only. The UI distinguishes pending, committed and failed local saves and identifies the external backup action. The [local-project contract](../engineering/LOCAL_PROJECTS.md) owns these boundaries. ## Workspace session discovery

The workspace lists restored or currently loaded models and non-default brief/reference context under **Continue working**. Model cards show current title, logical piece count and revision; brief-only cards return to the brief without loading geometry. Resume URLs retain the project slot even when a loaded file has a different model identity. Categories and sample search descriptions follow recognized model identity, with a Free-form fallback for other models. Search and category filters cover both current work and unopened sample slots. Active slots appear once, outside the sample cards, so a baseline poster/count never describes a different reopened model.

The blank entry says **Continue your model** or **Continue your brief** when that work exists. Client navigation resumes without reset and preserves undo/redo; reload restores saved content with fresh histories. An unused scratch slot retains **Start from scratch**. Cards explain local-browser storage and the external backup action. The four existing project slots remain the identity boundary; this slice adds no second independent scratch slot or rename operation. ## Beginner building and model-derived output

The default manual journey is **choose a piece → review its preview → Place brick**. The first supported piece starts on the floor; the next receives a valid visible attachment suggestion when the existing bounded core search finds one. Choosing a part alone never changes the model. **Attach to model** and **On the floor** are direct controls; numerical positions and detailed policies remain under **Advanced placement**, and selected-piece coordinates under **Advanced position**. Failed suggestions retain strict placement feedback. [The building-loop contract](../editor/EXPERIENCE.md#the-building-loop) owns target eligibility, validation and fallback details.

**Orbit** supplies the same navigation action across supported input devices without requiring a device choice. **Disassemble** starts with the topmost current model layer, frames one layer at a time and offers direct previous/current/next navigation plus **Show all layers**. Reassembly restores prior hide/focus choices. **Lift the roof** remains a distinct authored action. These are reversible view changes. The [experience contract](../editor/EXPERIENCE.md) owns gestures and edit locks.

Instructions prioritize the actual current model. Generated drafts save a 3D or top projection per step, initially frame its additions and offer **Whole build** for the assembled context. Long guides have ten-step pages. **Edit step** changes title/notes; **Arrange steps** exposes moves, split and merge. A separate undo/redo history survives route navigation; local saves and project backups retain the current guide and its source snapshot, with fresh histories on restoration. Regeneration from either generated or original-sample views protects edited work with an explicit replacement dialog. The original sample remains an explicitly labeled alternative. Height ordering, manual rearrangement and schematic nominal geometry do not establish physical buildability, a verified assembly sequence or exact part shapes. The [local-draft contract](../editor/EXPERIENCE.md#local-instruction-drafts-and-disassembly) owns generation limits, stale-guide controls and restoration behavior.
