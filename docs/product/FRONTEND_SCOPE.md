# Frontend scope

ID: FE-SCOPE-001

Owner/scope: frontend repository

Status: Specified

Baseline: execution brief 1.1.0 / consolidated product v0.0.3, 2026-09-24.

Implemented behavior is intentionally bounded: static navigation, filters/forms/dialogs, local reference selection, curated 3D display, supported grid edits, undo/redo, derived counts, baseline examples, local instruction drafts and presentation previews.

The [D1/D2 alignment](BASELINE_ALIGNMENT.md) preserves the broader product intent while distinguishing this frontend slice from product completion. Brief intent, visual language, construction system, technique, intended use and constraints remain distinct. Browser-local saves and explicit project backups retain the model, edited instruction document, brief, validated image bytes and manual calibration. PDF references retain metadata only. These references are not inferred measurements, enforced constraints or generated geometry. Storage is local to the browser and address, can fail or be cleared, and does not provide cloud synchronization. The [local-project contract](../engineering/LOCAL_PROJECTS.md) owns restoration, package contents and limits; model/editorial histories and camera state remain session-only.

The allowed edits are select, recolor among demo colors, translate by valid grid increments, set a numeric transform, rotate in quarter turns, duplicate a supported part, place a supported demo brick using a preview or numeric coordinates, and remove an unprotected part. Numeric X/Z coordinates support tenth-stud increments and Y supports twentieth-stud increments. Primary single-piece movement and rotation use a destination preview and explicit confirmation, preserving the existing instance in one relocation command. Multi-selection/group drafting retains horizontal dragging with one command on release; advanced numeric edits remain free-form drafts. Group protection is a local model invariant, not security. The predefined variant requires a compatible base revision and explicit apply.

The focused specialist continuation implements Build, Inspect and Present around one canonical model. Strict Connect and Grid placement use the same core validation at preview and commit; Free position remains an explicitly unverified draft. Multi-selection, nested groups and protection, focus/section/explosion, local experiments, same-footprint replacement, versioned project download/load, local reference pinning and real PNG export are editor-scoped. [Editor requirements](../editor/README.md) and [modeling](../editor/MODELING.md) define exact coverage. Geometric checks do not assess strength, stability, manufacturing tolerances or general mechanisms.

Single-brick inspection reuses the existing canvas to expose underside geometry. Roof access and assembly separation use authored, baseline-linked module metadata with a separation slider and guides. Current-model disassembly opens one layer at a time with an optional complete overview, equally for free-form models and samples. These are reversible display arrangements. Local instruction drafts have editable wording, saved 3D/top views, adjacent reordering, split/merge and independent undo/redo; they do not prove build order. Camera, inspection, assembly offsets, visibility and instruction edits do not change model coordinates, BOM or revisions. The modern shared shell and project-library home preserve a first-class blank-canvas entry alongside examples.

Excluded: endpoints, Server Actions, authentication/server databases, fake network services, AI SDKs or arbitrary prompt generation, network upload/OCR/PDF ingestion, production physics or manufacturer-certified snapping, validated automatic assembly planning, billing/checkout, invitations/notifications, publishing, realtime/sync, cloud persistence and speculative offline services. Native browser storage is limited to local project continuity. Backend/infrastructure application work is out of scope.

The specialist editor does not add a PDF production pipeline. Purchase/invite capabilities remain unconnected; project-file and PNG downloads are actual local browser outputs. Blank entry must open a usable empty model; sample exploration is never described as generation from user text.

## Capability coverage

The [catalog](../../src/fixtures/catalog.ts), [manifest](../../src/fixtures/editor/manifest.ts) and [modeling contract](../editor/MODELING.md) define the current subset. A capability is not enabled by selecting a visual style or describing a mechanism in the brief.

| Capability                   | Available in this frontend                                                                                                                                                                                                  | Explicit boundary                                                                                                                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Free-form subject and layout | Empty scene; manual composition across the supported demo library; numeric transforms, groups and reversible edits.                                                                                                         | No architecture-only category gate. Supported transform/catalog bounds still apply.                                                                                                                                           |
| Part identity and color      | Stable logical instances and named original demo definitions/colors; derived part-color quantities.                                                                                                                         | No manufacturer catalog mapping, verified real part-color combinations, availability or price. Decorative geometry may not correspond to a purchasable part.                                                                  |
| Basic stud construction      | Nominal rectangular parts, declared receiving slopes and one closed framed-door assembly; explicit Connect/Grid/Free placement, bounded occupied-volume checks and contact paths to ground.                                 | Profiles are original demo geometry. Decorative door panels and other unsupported shapes remain unverified; connection paths do not assess manufacturing fit, physical stability, strength or build order.                    |
| SNOT and hybrid construction | Brief preferences can record the intended technique; demo details without supported connectors can remain explicit drafts.                                                                                                  | No verified lateral connector profile or arbitrary X/Z-axis part orientation. Y-axis quarter turns are not SNOT capability.                                                                                                   |
| Technic and mechanisms       | A labeled visual rover study and manually positioned geometry.                                                                                                                                                              | No supported pin/axle/hinge family, verified revolute pose, kinematics, friction, load or continuous motion assessment. EDR-029 remains blocked by missing verified hinge metadata.                                           |
| Assisted design              | Accessible pre-authored courtyard roof comparison with explicit apply/undo and revision/protection checks; local command experiments remain distinct.                                                                       | No prompt-driven generation, reference analysis, provider, jobs or credits. The sample must not be represented as a response to the user's brief.                                                                             |
| References and design axes   | Project brief, local images, PDF metadata and manual image calibration retained in browser saves and portable project backups.                                                                                              | No PDF parsing/OCR, network upload, inferred geometry, automatic constraints or cloud reference library. Browser data may be cleared; retain an external backup.                                                              |
| Instructions and assemblies  | Curated baseline examples; editable drafts with per-step views, reorder/split/merge and separate history; focused schematics, reverse previews and individual layer inspection. Saved guides retain their source snapshots. | No proven insertion sequence, named subassembly planner, custom camera poses, automatic reconciliation, physical assembly test or production PDF booklet. Generated ordering is by height; editorial history is session-only. |
| Parts list and portability   | Exact scene quantities, per-row attachment/overlap review, illustrative owned/missing values, complete local project backups, legacy scene-file loading and real PNG output.                                                | Scene quantities are not a purchase list: no verified manufacturer mapping, real inventory/reservations, external sourcing or LDR/MPD import/export. Project backups omit model/editorial undo history and camera state.      |

These limits retain the wider D1 requirements as partial or deferred; they do not remove SNOT, Technic, useful free assistance, reliable instructions or digital distribution from the product. Any broader capability requires its own catalog provenance, command contract, coverage and evidence.
