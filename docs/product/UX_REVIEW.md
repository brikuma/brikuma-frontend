# Incremental usability review

ID: FE-UX-001

Owner/scope: frontend repository

Status: Workspace rediscovery, beginner-building, editable instructions, local continuity and placement recovery and single-piece repositioning implemented; follow-up backlog open

Baseline: local frontend walkthrough and source inspection, 2026-09-25.

## Evidence and scope

An agent operated Chrome at `http://localhost:3000`: workspace → **Start from scratch** → select **Brick 2×2** → **Place** → confirm one part → return to **Workspace**. The model was absent from the project cards; the unchanged **Start from scratch** action reopened the same model. This was an agent walkthrough, with no human participants or usability measurements. Other routes and journeys have not been exhaustively audited.

The additional initial findings below came from source inspection. The corrected brief-only journey was subsequently checked live in the production export. Validation results for the changed implementation belong in [acceptance evidence](../delivery/ACCEPTANCE.md).

The owner then reported that basic modeling was still difficult: technical coordinates, camera device selection, a Disassemble action that only lifted the roof, scratch-model friction and unsatisfactory instructions. The owner subsequently confirmed that the tested two-piece attachment behaves correctly and asked to continue with the other steps. That confirmation is limited to their reported case; it is not broad physical or usability validation. The second slice below combines those reports with code inspection and targeted regression scenarios. The [reference register](../references/README.md#september-25-product-and-competitor-conversations) records the additionally inspected product/competitor conversations and their source limitations.

## Fourth slice: retain and recover the project

Source inspection found that reload cleared all authored work, geometry-only downloads lost edited guides/brief/references, and file/study replacement could discard instruction-only edits without confirmation. The owner asked to continue toward a frontend usable independently of a future backend. [FE-DEC-019](../DECISIONS.md#fe-dec-019-local-project-continuity-and-portable-backups) supersedes the earlier session-only lifetime.

Model, brief, image references/calibration and the guide/source now save in the browser and can be backed up together. Hydration precedes default scene loading; saved status follows transaction completion. Failure and multi-tab conflicts remain visible without overwriting prior work. Import validates before replacement, and discard protection includes generated/edited guides. Pending image validation does not count as a completed save. The [local-project contract](../engineering/LOCAL_PROJECTS.md) specifies limits, recovery behavior and excluded histories.

This addresses continuity, not full production readiness. Independent scratch identities/rename, beginner mixed-piece repair journeys, named subassemblies, instruction reconciliation, physical validation and real-device accessibility/performance remain outstanding. [Acceptance](../delivery/ACCEPTANCE.md) records actual checks separately from this change description.

## Sixth slice: reposition a placed piece

An agent continued the production-browser journey with a Plate 4 × 4 supporting a Brick 1 × 2. Selecting the brick and choosing Rotate 90° committed immediately; its nominal contact count fell from two to zero. Separately, core source inspection showed that the default half-stud translation could also detach the placed piece. The rotation was observed live; the translation finding was code-inspected. Neither is a human usability study or physical test.

| Finding                                                                            | Reproduction or inspection path                                                                                                                | Correction in this slice                                                                                                                                                                              | Remaining boundary                                                                                                                                                                        |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UX-15: Primary Move and Rotate bypass the placement rules a beginner just learned. | Place the supported brick described above, select it, then Rotate. Inspect the default half-stud Move command for the same odd/even footprint. | Open **Reposition piece** with a destination preview and explicit **Apply move** or **Cancel move**. Use an atomic relocation of the existing source, preserving identity, color, group and quantity. | Advanced numeric and rigid multi-selection/group edits remain explicit drafts. Moving one support does not move dependent parts or guarantee that the remaining assembly stays connected. |

The source remains canonical during preview, while its old rendered position is hidden. Only that source is excluded from destination collision/contact queries; real hidden obstacles remain checked. Cancellation creates no history, and stale or protected edits reject without mutation. Initial policy follows the current piece: a valid existing connection uses Attach, a supported grounded piece uses On the floor, a detached supported piece above the floor starts blocked in Attach, and unsupported geometry uses a visibly unverified Free draft. Color remains unchanged and Repeat is unavailable.

[FE-DEC-021](../DECISIONS.md#fe-dec-021-preview-and-apply-single-piece-repositioning), [experience](../editor/EXPERIENCE.md#the-building-loop) and the [core relocation contract](../engineering/CORE.md#single-piece-relocation) own the interaction and command boundaries. Implementation coverage is mapped in [traceability](../TRACEABILITY.md#single-piece-repositioning--2026-09-25); [acceptance](../delivery/ACCEPTANCE.md) owns actual post-change results. This slice does not establish complete product usability, physical connection strength or a verified build order.
