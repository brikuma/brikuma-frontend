# Product baseline alignment

ID: FE-ALIGN-001

Owner/scope: frontend repository

Status: Source review and frontend scope mapping; execution evidence remains separate

Baseline: supplied D1 and D2 v0.0.3 Markdown documents, 2026-09-24. See the [source register](../SOURCES.md).

D1 defines the intended product; D2 defines its contracts and invariants. The current assignment implements a browser-local frontend slice of that product. A frontend demonstration does not complete a whole D1 feature, prove a D2 invariant across a service, or remove either requirement from the product. D3 was not supplied; its acceptance criteria, gates and user-story coverage are not inferred.

The product remains a general creative environment with free-form creation, assisted design, distinct construction capabilities, coherent parts/instructions and digital distribution. The courtyard is one example, not the required subject. Later visual and editor refinements change presentation and local tools; they do not turn the product into an architecture-only renderer or replace assisted design with a generic CAD application.

## Product continuity acceptance

The frontend follow-up must keep the source brief and references accessible while moving between brief, editor, BOM and instructions; expose the pre-authored assisted-design preview without obscuring manual building; and keep project navigation reachable outside file management. The four route-keyed project slots retain saved geometry, guide/source and context in the browser, with hydration before fixture loading. A project-file replacement uses its validated context and current model as the new baseline; legacy scene import starts with empty context and no local guide. Restoring the existing model baseline preserves its context. The [local-project contract](../engineering/LOCAL_PROJECTS.md) defines save feedback, recovery and backup boundaries; undo histories and camera state are not durable. Metadata and camera/inspection changes must not rewrite the model, counts or revision. A stale roof proposal must be rejected, and undo must recover the prior model.

These are reviewable expectations. Their executed checks, independent code review and remaining limits are recorded separately in the [current acceptance ledger](../delivery/ACCEPTANCE.md). Earlier [editor evidence](../editor/EVIDENCE.md) remains historical evidence for its recorded candidates; it is not inherited automatically by changed code.
