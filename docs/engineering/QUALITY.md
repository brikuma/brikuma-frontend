# FE-QUALITY-001 — Quality gates

Owner: frontend. Status: implemented; evidence in [acceptance](../delivery/ACCEPTANCE.md). Baseline: execution brief 1.1.0. Related: [dependencies](DEPENDENCIES.md), [core](CORE.md), [review](../ai/REVIEW.md), [index](../README.md).

Use Node22.23.2 and npm10.9.8, independently installed frontend dependencies. `npm ci --ignore-scripts` preserves the reviewed lifecycle boundary; `npm run hooks:install` installs Husky into this repository. Never change global Git configuration. `npm run check` runs lint, formatting, generated Next route types, full/core TypeScript, graph checks and negative self-tests, pure/component tests, hook self-tests and local documentation checks. `npm run build` creates static `out/`; `npm run preview` serves that directory on loopback port4173 with a native development-only static file server.

The deterministic test runner uses one worker (`maxWorkers: 1`), retaining isolation between all 55 test files. This replaces CPU-derived concurrency after both four-worker and fresh two-worker verification produced timeouts; the current two-CPU hosted runner's effective worker count remains one. [Acceptance](../delivery/ACCEPTANCE.md#deterministic-concurrency-and-restoration-observation--2026-09-25) and [FE-DEC-027](../DECISIONS.md#fe-dec-027-conservative-deterministic-concurrency-and-callback-observation) record the evidence and policy. All 798 tests retain their assertions, default timeouts and retry policy; test deadlines are not a UI performance benchmark. Component tests that inspect a callback payload must await that callback rather than infer its completion from separately rendered state. Scope accessible control queries to their existing semantic region when the interaction belongs to that region, avoiding repeated catalog-wide accessible-name searches. Keep real user events, setup, assertions and normal accessibility filtering; query scoping is test-harness work, not a product performance claim.

## Staged gate and evidence

Before an agent commit, stage explicit owned files, then use `node scripts/quality.mjs verify` to execute deterministic checks against matching staged/worktree inputs. Inspect the candidate diff and results read-only. Record findings in an ignored JSON array under `artifacts/`, then `node scripts/quality.mjs record-review <reviewer-label> <findings-json-path>`. The helper records the exact candidate tree, repository, base commit, lockfile hash, Node/npm versions, timestamp and actual command/log results. It does not prove review truth. Unresolved findings block; label a self-review honestly.

Pre-commit uses `npm run check:commit`: snapshot and review integrity plus read-only lint-staged. Relevant unstaged/untracked source, tests, configuration and docs are rejected non-destructively; unrelated preexisting user `.agents`, `.claude`, and `skills-lock.json` are untouched. Changed trees invalidate review. Partial staging is not silently expanded. Commit-msg runs exact local commitlint; pre-push runs complete checks, production build, bundle budgets, browser journeys and axe. Hook execution never installs packages or accesses a model/network. CI reruns committed-tree checks independently of local evidence.

Pre-push requires those inputs to match committed `HEAD` before running and after each gate, so staged or unstaged fixes cannot validate a different published revision. A disposable regression test covers the valid committed state and both refusal cases without deleting work. This guard was added following the separate exact-candidate review.

## Architecture authority

[dependency-cruiser config](../../.dependency-cruiser.cjs) analyzes resolved aliases, reexports, type-only/static dynamic imports, cycles, unresolved modules, undeclared packages, pure core, public contracts, passive fixtures, product-agnostic primitives and renderer location. [Negative fixtures](../../tests/architecture/boundaries.test.mjs) are generated only under ignored artifacts. Scoped ESLint prohibits core browser globals, uncontrolled randomness, time and framework directives. `tsconfig.core.json` excludes ambient DOM/Node/React types. These checks constrain dependencies; human review still owns semantic domain boundaries.

## Browser and limitations

Playwright uses installed Google Chrome locally and its pinned full Chromium distribution in CI (`channel: "chromium"`, new headless mode). The explicitly WebGL-disabled fallback test selects the same browser channel. The existing CI browser-install command already installs this binary. Firefox/WebKit or real-device tests require explicitly available browsers. A software renderer does not establish GPU frame rate. Test descriptions and failures remain English. Automated axe is an aid to WCAG2.2AA review, not certification.

Full Chromium follows the upstream recommendation for accurate application end-to-end testing. It shares the pinned engine version with the smaller headless shell, but GPU behavior and performance may differ. This choice does not promise faster rendering or resolve a failed hosted run by itself. [FE-DEC-030](../DECISIONS.md#fe-dec-030-full-chromium-for-ci-browser-journeys) records the source rationale and [acceptance](../delivery/ACCEPTANCE.md#full-chromium-ci-browser-selection--2026-09-27) records validation separately.

CI explicitly launches Chromium with `--use-gl=angle --use-angle=swiftshader` to select the complete SwiftShader OpenGL ES driver, matching the local software-rendering harness. Chromium distinguishes this from its WebGL-only fallback. The editor matrix reuses that Chromium project; Firefox and WebKit receive no Chromium flags. Local launch options and browser channels remain unchanged. This test-environment choice preserves rendering quality, browser and accessibility coverage, assertions, budgets and retries; it does not establish the renderer actually used by an earlier hosted run or predict hardware-GPU performance. [FE-DEC-025](../DECISIONS.md#fe-dec-025-explicit-ci-software-rendering-driver) records the decision and [acceptance](../delivery/ACCEPTANCE.md#explicit-ci-software-rendering-driver--2026-09-25) records validation separately.

CI records a full Playwright trace on the first retry (`on-first-retry`), following the upstream [CI debugging recommendation](https://playwright.dev/docs/best-practices#debugging-on-ci). The initial attempt has no action-by-action trace; failure screenshots, test-runner output and the HTML report remain available. The existing single retry records the full trace, including DOM snapshots and screenshots. Local runs retain `retain-on-failure`, and `--trace on` remains available for explicit diagnosis. Failure-only artifact upload is unchanged: a successful run with a recovered retry does not upload browser diagnostics. This reduces routine instrumentation, not assertions or failure enforcement; it is not proof of a renderer performance fix. [FE-DEC-029](../DECISIONS.md#fe-dec-029-upstream-renderer-and-ci-tracing-guidance) records the related lifecycle patch and evidence limits.

The main suite contains 49 browser cases and a separate ten-check accessibility suite. Responsive renderer coverage uses three fresh browser contexts: quality-profile changes and screenshots; Quality camera and HTML selection; and Quality roof/focus/module assembly with context-loss fallback. These cases retain the original actions, assertions and screenshot artifacts, with unchanged per-case budgets and retries. Separating responsibilities prevents earlier screenshot work from consuming an unrelated interaction's whole-test budget and makes failures independently actionable; it is not a rendering-performance fix. [FE-DEC-026](../DECISIONS.md#fe-dec-026-isolated-responsive-renderer-cases) records this scope change.

In CI, Playwright uses line and GitHub reporters alongside the existing HTML report, so failure details are visible before the job finishes. `maxFailures: 1` stops the browser suite after its first permanently failed case, after the existing single retry. Local runs retain unlimited failures (`maxFailures: 0`). Test selection and assertions remain unchanged. An early-stopped suite fails the browser command and the mandatory `required` job; tests not reached are not reported as passed. Failed CI runs retain the Playwright result and HTML report directories plus authored captures in `artifacts/screenshots/`, `artifacts/editor/` and `artifacts/editor-ux/` for seven days through the pinned official upload action; missing diagnostics after an earlier check failure are allowed, and hidden files are excluded. This diagnostic policy does not resolve an underlying browser failure.

The default whole-journey timeout is 120 seconds in CI and 30 seconds locally. This cumulative execution budget is separate from the unchanged five-second default assertion timeout; existing explicit 60- and 90-second test overrides remain unchanged. The hosted deterministic job has a thirty-minute deadline for checks, build, browser journeys and accessibility together. Retry count, fail-fast behavior, assertions and required jobs remain unchanged. These execution budgets accommodate constrained CI rendering; they are not UI response-time targets or performance acceptance evidence. [FE-DEC-024](../DECISIONS.md#fe-dec-024-ci-browser-execution-budgets) records the reason and limits, and [acceptance](../delivery/ACCEPTANCE.md#ci-browser-execution-budgets--2026-09-25) separates local simulation from hosted results.

Remote protections are owner configuration: require the frontend `required` job, disallow bypass/force push, require review of policies/workflows. No remote protection is configured by a local file. Local hook timings and actual results are recorded in acceptance, not presumed passed.

## Verified static build delivery

The owner selected downloadable builds with hosting deferred on 2026-09-27. The Frontend workflow supports push, pull request and manual runs. Its deterministic job waits for the security job to succeed, then runs all checks against the checked-out revision. Only after the build, bundle budgets, 49 browser cases and ten accessibility checks pass does it upload the same `out/` directory that the browser tests exercised. No rebuild occurs between testing and upload. Missing output or an upload failure fails that job and the final `required` gate. A failed or skipped security job prevents build delivery.

Artifacts are named `brikuma-frontend-<commit-sha>-<attempt>`, use the existing pinned official upload action, exclude hidden files and expire after seven days. The attempt suffix keeps reruns distinct without overwriting earlier evidence. Use a successful workflow run with a successful `required` job; for pull requests, the SHA identifies the tested merge revision. Download from **Actions → Frontend → selected run → Artifacts**, or select the exact run and artifact with the authenticated CLI:

```sh
gh run download <run-id> --repo MatteoVincenti/brikuma-frontend \
  --name brikuma-frontend-<commit-sha>-<attempt> --dir ./frontend-build
```

The archive contains static site files, with `index.html`, exported routes, assets and third-party notices at its root. It requires a static HTTP server; opening HTML directly from the filesystem does not validate application routing. Download access follows the private repository's permissions. This delivery contract does not enable hosting, a public release, physical validation or branch protection. The root integration checkout selects an exact frontend commit; choose its matching successful frontend run when retrieving that build. Actual hosted results and artifact download checks belong in the ignored run evidence, separately from this configuration.
