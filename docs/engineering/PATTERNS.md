# FE-PAT-001 · Implemented patterns

Owner: frontend. Scope: local model commands and original fixture authoring. Status: implemented. Baseline: frontend execution brief 1.1.0 / product v0.0.3. Related: [core](CORE.md), [architecture](ARCHITECTURE.md), [quality](QUALITY.md). Source: execution brief section 5.5 and [YAGNI](https://martinfowler.com/bliki/Yagni.html).

| Problem                                                                         | Selected pattern             | Implementation and proof                                                                                                                                                                                                                                     | Alternative / reason                                                                                                                               |
| ------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Supported edits must share validation, protection, revisions and undo behavior. | Command plus bounded Memento | Discriminated `EditCommand`, `applyCommand`, and readonly snapshots in [commands.ts](../../src/core/model/application/commands.ts). [Tests](../../tests/unit/model.test.ts) verify undo/redo, branch replacement, a 2-entry test bound, and atomic variants. | A generic command bus or event log adds unused infrastructure. One plain discriminated union is sufficient.                                        |
| Fixture and UI input must produce a valid model aggregate.                      | Validated factory            | `createModel` in [model.ts](../../src/core/model/domain/model.ts). Tests independently introduce duplicate IDs, unsupported keys, out-of-grid positions, and exceeded limits.                                                                                | Public unchecked nested mutation would duplicate invariants in UI controls. A class for each value would add ceremony without additional behavior. |
| Core cannot depend on rendering or storage shapes.                              | Adapter / inward dependency  | Public plain numerical transforms and shape definitions in [public.ts](../../src/core/model/public.ts) are mapped by the scene renderer outside core.                                                                                                        | Direct `THREE.Vector3` fields would contaminate the pure core. No injected persistence port is needed for a session-only aggregate.                |
| Dashboard and instruction posters must agree with actual logical scene data.    | Build-time translation       | [Preview generator](../../scripts/generate-previews.mjs) compiles fixture source and projects the same instances into original SVG assets and [lightweight counts](../../src/fixtures/scene-counts.json).                                                    | Hand-drawn unrelated previews would drift from counts and model geometry. A rendering service would violate frontend-only scope.                   |

There is no strategy abstraction because there are not two implemented competing algorithms with one meaningful contract. Fixture authoring helpers are deterministic data construction, not mock services. Existing patterns are reused for every supported command; no base entity, base repository, DI container, CQRS system, or general workflow engine exists.

The public `previewVariant` query reuses the existing Command pattern on a temporary immutable session, so preview compatibility, protected-group failures, and quantities have the same owner as application. No new abstraction is required. Pure tests verify preview/apply count agreement and non-mutation on compatible, stale, and protected input.

UI composition and component-specific interaction contracts are documented separately in [components](../design/COMPONENTS.md). Patterns do not replace accessible primitive APIs or independent user-oriented tests.
