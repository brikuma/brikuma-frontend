Checked: 2026-09-24. Scope: interaction contracts relevant to this local editor. The four primary documentation pages below were opened during this execution. No competitor application was installed, interacted with or benchmarked. These observations establish documented behavior, not product-wide quality, defect prevalence or comparative performance.

| Source                                                                                               | Evidence supported by the page                                                                                                                                                                    | BRIKUMA decision or hypothesis                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S01 · [Studio Snap](https://studiohelp.bricklink.com/hc/en-us/articles/5412087360919-Snap)           | Snap aligns compatible connection points and can reorient selected pieces. Ground alignment and connection-point alignment are described separately. Hidden parts are excluded from snap targets. | Expose Connect/Grid/Free position and an adjacent orientation policy. Visible target eligibility is distinct from hidden pieces remaining in physical diagnostics.                          |
| S03 · [Studio Connect](https://studiohelp.bricklink.com/hc/en-us/articles/6481651047319-Connect)     | The tool lets users choose source and target connecting points; its documentation explicitly separates this operation from collision consideration.                                               | Manual connector choice is an established baseline. The proposed combination adds a visible preview and an independent supported occupied-volume result; it is not claimed as an invention. |
| S04 · [Studio Collision](https://studiohelp.bricklink.com/hc/en-us/articles/5412820155927-Collision) | Guidance acknowledges approximate detection, dependence on render detail and potential resource cost for large designs.                                                                           | Keep diagnostics in pure model geometry, independent of visual quality, and label unsupported coverage. Measure cost instead of inferring it from scene appearance.                         |
| S09 · [LDCad basic editing](https://www.melkert.net/LDCad/docs/basicEdit)                            | The tutorial explains editing planes, absolute/relative grids and grid versus part snapping. It says missing snap metadata can require grid placement.                                            | Make plane and increments discoverable and keep an explicit grid fallback. A visible model does not establish supported connectors or mechanical validity.                                  |

## Testable hypotheses and implemented limits

| Hypothesis                                                                                  | Observation needed to support it                                                                                                   | Current status                                                                                                             |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Explained placement reduces mistaken commits and recovery time.                             | Matched tasks with the same placement kernel, controlled explanation exposure, mistake/cancel/undo counts and recovery timing.     | Candidate/orientation/coverage UI implemented; controlled comparison and human outcomes not measured.                      |
| A reversible focus lens helps people repair interior geometry without losing hidden pieces. | Correct-ID selection, return-to-view success and unchanged model membership after U3.                                              | Temporary isolation and separate hidden state implemented; human transfer-task result not measured.                        |
| Exact change impact makes local experiments easier to accept safely.                        | Participant identifies affected IDs/protected scope and correctly rejects stale proposals in U4.                                   | Real command previews, stale validation and atomic acceptance implemented; comprehension not measured.                     |
| Explicit precision controls reduce mode mistakes.                                           | Plane/pivot/orientation explanations, failed edits, accidental movements and help requests across novice/experienced participants. | Numeric controls and bounded planes/pivots implemented; general CAD or arbitrary rigid orientation is outside this subset. |
| One canonical model preserves trust across task modes.                                      | Equal IDs/revision/count before and after inspection/presentation, with actual exported pixels matching the declared scene.        | Shared model architecture implemented; executed browser/export evidence must be read separately.                           |
