# Editor model and supported geometry

Status: implemented pure contracts; executed evidence belongs to [evidence](EVIDENCE.md). The existing [core contract](../engineering/CORE.md) and [public API](../../src/core/model/public.ts) remain the context owners. No second model context or framework dependency is introduced.

## Coordinate and identity contract

Canonical values retain the existing right-handed, Y-up stud-pitch coordinate system. One stud pitch is one model unit; nominal brick and plate body heights are 1.2 and 0.4. A transform positions the body center and permits only quarter turns about Y. X/Z use 0.1-stud values, Y uses 0.05. Positions are finite, bounded by the editing policy, with Y nonnegative; scale, skew and reflection keys are rejected. Dimensions are nominal original demonstration values, not manufactured tolerance measurements.

`fromLDrawPoint` translates a future source point as `(x, -y, -z) / 20`; this changes basis by a proper 180-degree rotation about X, preserving handedness. Existing procedural geometry is already Y-up and must not be converted again. `rotateVector` maps local translation vectors through the canonical quarter turn. No LDraw geometry import is implemented. LDraw's matrix conventions are not silently applied to current transforms.

Stable part IDs belong to logical instances; render buckets, studs, shells, guides and ghosts never allocate identities. Group labels may change without changing IDs. Groups have optional `parentId`; validated construction rejects missing parents and ancestor cycles. Group membership changes preserve world transforms because group transforms are not stored.

## Commands and history

[Commands](../../src/core/model/application/commands.ts) retain existing single-part operations and add atomic `translate-selection`, `rotate-selection`, `recolor-selection`, `remove-selection`, `create-group`, `rename-group`, `reparent-group`, `move-to-group`, `replace-part`, `duplicate-selection` and `place`. Every command validates the complete result before accepting it. Bulk rotation uses one explicit world pivot, preserves distances, and rotates all members rigidly. User interfaces submit the complete affected IDs when operating on groups; `getGroupInstanceIds` includes descendants.

Protection is inherited from ancestors. Every affected instance and destination group is checked before an edit; one protected member rejects the entire operation. Explicit protection changes may unlock that group, but cannot bypass a protected ancestor. Protection changes enter undo history without invalidating geometry revision. Other accepted model changes allocate monotonically increasing session revisions. Loaded `model-id-local-N` revisions continue at N+1. Undo/redo restore exact snapshots; branching discards redo. Default history retains 40 model snapshots containing values only, never geometry resources. A zero history limit retains no preceding snapshot. No-op commands return `no-change`, do not advance revision and do not enter history.

`duplicate-selection` receives ordered source IDs, equally sized unique new IDs and one translation delta. It validates every source's inherited protection and the complete resulting aggregate before one history/revision update. It preserves colors, definitions, group membership, rotations and relative placement. Duplication is a draft operation: it does not assert collision-free placement. The UI selects all copies and requests Move. Previously hidden physical members remain hidden; group hide membership is materialized as instance IDs so new copies are visible even inside a previously hidden ancestor.

`getSelectionBounds` returns the nominal body envelope of the supplied IDs, using the declared width/depth/height and quarter turns. It excludes top studs, cosmetic geometry and display offsets. Empty, missing or unresolved selections return unavailable. It supplies inspector dimensions and the initial horizontal duplicate offset; it is not diagnostic geometry or a manufactured measurement. [Selection duplication tests](../../tests/unit/duplicate-selection.test.ts) cover atomic protection, identity allocation contracts, limits, rigid offsets and history.

## Placement and independent coverage

The `place` command takes `instance`, `baseRevision`, and an explicit `placement` policy:

| Policy        | Implemented validation                                                                                                                                                                |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Connect       | Supported source profile, coincident supported receiver/stud, no conservative material conflict, no overlapping unsupported geometry, current revision and ordinary model invariants. |
| Grid          | Footprint-aligned one-stud horizontal and 0.4-stud vertical increments above the ground; known material conflicts block; unsupported coverage remains a stated limitation.            |
| Free position | Ordinary model invariants only. Connections and overlap are not placement acceptance claims.                                                                                          |

Existing unrestricted add/transform commands intentionally support design drafts. The UI must use `place` for strict connector placement; preview and commit both use the same pure validation. Hidden pieces remain physical members because diagnostic APIs never receive visibility flags. A preview creates no history or canonical instance.

`getPlacementCandidates` receives a model, catalog definitions, source definition/transform, source receiver index, orientation policy and optional eligible target IDs, excluded IDs, maximum distance, previous candidate and result limit. The bounded source/target subset includes integer rectangular brick/plate footprints with heights 0.4 or 1.2, explicitly declared receiving slopes, and the original framed-door assembly described below. Top studs and underside receivers are distinct capabilities; smooth tiles and receiving slopes receive but do not offer top studs. Round parts, arches and other custom architectural details can render or expose legacy nominal sites while remaining outside strict Connect coverage.

Keep orientation considers only the starting quarter turn. Align considers the four discrete turns. Candidates align a selected source receiver to a target stud; rank by required translation, orientation change, then stable identity. Expensive occupied-volume checks run only on the bounded ranked result list, rather than on every possible connector. Default search bound is six studs, with at most eight displayed candidates (caller may request up to 32). The previous candidate remains first within 0.25 stud of the best distance. This is a world-space manual-selection heuristic, **not a screen-space magnetic snapping implementation**. Screen-distance ranking and zoom-aware enter/exit thresholds remain unimplemented. Candidate diagnostics report occupied targets rather than hiding their explanation; strict commit rejects conflicts. No physical probability or certainty percentage is computed.

## Occupied-material diagnostics

[Diagnostic rule `original-building-shell-v2`](../../src/core/model/domain/diagnostics.ts) is independent of rendering quality and uses a broad bounding filter followed by composed occupied volumes. Supported rectangular geometry includes four side walls, top shell, cylindrical studs, underside hollow space, annular support tubes or pins. [Nominal geometry profiles](../../src/core/model/domain/nominal-geometry.ts) share material definitions and deformation parameters with the renderer. The volumes retain original nominal side/body clearances and approximate details; rounded bevels are conservatively enveloped. AABB intersection alone is not a final result. Legal aligned studs enter receiver voids and are not flagged merely because their broad bounds overlap.

The catalog explicitly opts three original shapes into `receiving-slope-v1`: Roof slope 2 × 4, Roof tile slope 1 × 2 and Timber roof slope. The profile requires an integer rectangular footprint, no top studs and a sufficient nominal height; it is not inferred from a sloped silhouette. Conservative narrow slices enclose the same receiving-shell deformation used by the renderer, with underside connector voids retained. Other slopes and decorative roof details remain unsupported. Quarter-turn placement does not introduce arbitrary roof angles, physical clutch verification or manufacturer mapping.

`framed-door-v1` supports one original Door with frame 1 × 2 × 4 assembly, nominally 2 × 1 × 4.8 studs. The receiving sill, uprights, header, recessed leaf, pin journals and retaining caps are authored together as one closed logical instance, using shared material volumes for rendering and overlap checks. The sill has two underside receiver sites and the header has two top studs. It can connect through those external sites; the old Tower door leaf and other decorative panels do not acquire connectors. This is a fixed closed assembly with no opening command, revolute solver or verified manufacturing tolerances. One assembly is one scene quantity, not a verified retail item or a manufacturer component breakdown.

The numerical intersection tolerance is 0.00001 stud. It is separate from clearances, pixel target sizes and visual antialiasing. Annular cylinders are compared by outer/inner radial extents; box/cylinder tests compare nearest/farthest extents. Only Y-axis cylindrical volumes and quarter-turn boxes are supported. Conservative conflicts can include material near omitted bevel details; they are geometric preview diagnostics, not manufacturing proof.

`diagnosePlacement` returns category, rule, model revision, current state, supported coverage, conflicting IDs, unchecked IDs and checked pair count. `no-conflict` means no intersecting supported conservative volumes. Unsupported intersecting geometry returns `not-checked`; unsupported shapes outside a known broad bound do not create a fabricated collision. `diagnoseModel` reports conflicts and unsupported instance IDs for the model. Physical assessment is always `not-evaluated`. Displayed results must be marked stale whenever their stored revision no longer matches the document. Quality and visibility cannot change the result because neither is a diagnostic input.

## Attachment assessment and scene quantities

[`assessAttachments`](../../src/core/model/domain/attachment-status.ts) returns the current revision, one status and neighboring contact IDs per logical instance, totals for each status, and `physicalAssessment: not-evaluated`. Supported pieces whose nominal body bottoms meet the ground are `ground-supported`. An undirected graph of supported stud/receiver contacts identifies `connected-to-ground` pieces, including a piece connected through an upper bridging part. A supported floating piece or floating connected island is `unattached`; geometry outside the supported profiles is `unsupported`, even if its nominal body touches the ground. Unsupported pieces never supply an inferred connection path.

This assessment does not measure stability, strength, insertion order, manufacturing fit or overlap. [Scene inventory](../../src/features/parts/inventory.tsx) reports occupied-volume conflicts separately, preserves every part/color quantity, and counts each instance needing review once even when it has multiple issues. Rows expose connection statuses, overlap counts and reviewable instance IDs; the review filter does not change scene totals. Hidden instances remain in both quantities and assessment. Owned/missing values remain illustrative, and original demo identifiers have no verified manufacturer mapping. Scene quantities are not a purchase list. [Attachment tests](../../tests/unit/attachment-status.test.ts) and [inventory interaction tests](../../tests/component/inventory-attachments.test.tsx) cover grounded paths, floating islands, unsupported pieces, overlap reporting, exact quantities and repair updates.

## Experiments and replacement

[Experiment previews](../../src/core/model/application/experiments.ts) execute a real command on an isolated session and derive actual added, removed, transformed, recolored and replaced IDs, touched groups, count delta and stale-check implications. The preview records both base revision and a full canonical signature including group protection. Accept revalidates both and reruns the original command into the current session as one transaction. Discard does not mutate anything. The signature is a local equality guard, not a cryptographic or security claim.

Same-footprint replacement preserves instance identity and its body-bottom height. Width/depth must match. `getReplacementFeedback` reports unchanged/changed connectors for the bounded supported subset; otherwise it reports unknown. A changed height can affect neighboring geometry or contacts; replacement is a draft edit and does not assert compatibility with the surrounding assembly. No general mirrored-part or mechanical replacement solver is implemented.

## Explicit local files

[Project files](../../src/core/model/application/project-file.ts) use `format: brikuma-scene`, `schemaVersion: 1`, and `coordinates: stud-y-up-quarter-turn-v1`. Serialization contains canonical model data only: no camera, renderer object, geometry asset, image reference, automatic persistence or remote save. `parseProject` rejects malformed/future versions, unknown keys, nonfinite/off-grid transforms, scale/reflection, unknown catalog/color references, duplicate identities, missing groups, hierarchy cycles and control characters in labels. The parser limit is 5,242,880 UTF-8 bytes (5 MiB) (the browser picker separately limits file bytes to 4 MiB), groups are bounded at 1,000, and part count uses the current editing policy. Import validates fully before the browser adapter replaces a document; no partial load exists. The browser UI owns the explicit discard-unsaved-work confirmation.

## Nominal centimeters and optional architecture templates

Canonical coordinates and serialized files retain their existing stud-pitch units. Public conversion helpers use 0.8 cm per nominal pitch; all length inputs convert back before invoking core commands. X/Z numeric precision is 0.08 cm and Y precision is 0.04 cm. Displayed dimensions exclude separate visual stud height, as before. This is a nominal scale convention, not a measured manufacturing tolerance. The [LDraw unit reference](https://www.ldraw.org/article/218.html) defines 20 LDU per stud spacing and an approximate 0.4 mm per LDU.

The optional deterministic building helper composes existing supported demo parts into a house or three-wing courtyard, complete or foundation/walls/roof sections. The default courtyard footprint is 25.6 × 19.2 cm. It previews an additive experiment and accepts it as one undoable command. Existing parts are preserved; stale/protected proposals, conflicting volumes and new pieces without a supported path to the ground are rejected. Window openings contain no invented attached glazing. Each closed framed door remains one supported demo assembly. This narrow helper is neither a general prompt generator nor a restriction on the free-form editor.
