## Local performance baseline

[The repeatable runner](../../scripts/editor-performance.mjs) used Chrome 153.0.8010.53, reported `ANGLE Metal Renderer: Apple M2`, 1440×900 CSS pixels, DPR 1, Auto/conservative quality, loopback static output with no CPU/network throttle. A fresh browser context measured empty activation; later scene switches were warm. Fixture source hashes, build identity, actual counts and measurements are in the JSON. This is a local lab result, not a claim about all hardware or every 5,000-piece model.

Shell observation was 146.8 ms from the runner's navigation start; the first real frame was 550.0 ms and scene-ready 552.8 ms on the page performance clock. The first Add/Place task took 178.8 ms including automation/DOM overhead. These are separate observations, not one combined readiness metric.

Those task durations include automation and assertions; they are not continuous pointer latency measurements.

All three scenes added zero frames in the measured settled idle interval. This establishes observed GPU-resource count behavior, not a complete JavaScript heap/listener leak proof.
