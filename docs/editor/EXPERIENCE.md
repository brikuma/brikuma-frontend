# Editor experience and usability protocol

Owner: frontend. Scope: the browser-local `/editor` workbench. This document describes implemented interaction contracts and a proposed usability study; it is not a browser-test or participant-results report. Check [evidence](EVIDENCE.md) for executed checks and [modeling](MODELING.md) for authoritative command and geometry limitations. The existing [accessibility specification](../design/RESPONSIVE_ACCESSIBILITY.md) remains the broader application policy.

## Workspace and task modes

The shared application header remains in place. The editor's document strip shows derived part count, local revision, Build/Inspect/Present, history and explicit local files. Parts, Structure and References occupy the left panel; Selection, Checks and Activity occupy the right. The Changes rail opens below the model and reserves layout space. Projects save locally in the browser under the [local-project contract](../engineering/LOCAL_PROJECTS.md). There is no assistant service, cloud save or physical certification.

Build permits supported canonical commands. Inspect and Present permit selection, camera and presentation changes. The workbench rejects edits and history navigation outside assembled Build, including while section, step, exploded, single-part inspection or export views lock editing. Experiment acceptance rechecks this assembled state, the exact base model and protected scope. Selection and model values persist when switching task modes. Camera poses are remembered per mode during the mounted session; first entry inherits the current view. Camera continuity across projection changes or unusual mode sequences remains a browser acceptance concern, not an assertion based solely on source.

The initial camera uses an orthographic isometric view. Explicit controls provide all six axis views, isometric/home, perspective/orthographic, fit model, fit selection, zoom, orbit-left/right and pan in four directions. Fit excludes the floor and uses part bounds. A camera direction parallel to the active editing plane is disabled during manipulation; an isometric view supplies a usable placement ray. No automatic turntable runs.

## Catalog and selection contexts

The user-supplied master UI/UX brief prompted an editor-focused follow-up. The existing BRIKUMA brand, canonical tokens, static-export boundary and truthful local capabilities remain authoritative. This pass does not implement the brief's AI service, cloud autosave, authentication, pricing, community delivery or physical certification, and does not replace existing product pages.

Catalog search matches names, original IDs and category terms, normalizing case, spacing and dimension separators. Tiles are distinct from studded plates and roof details. All parts, Favorites and Recent combine with Currently used and category filters. Favorites/filter state survives switching panels and responsive panels within the mounted workbench. Recent lists at most 24 definition IDs from committed catalog placements; a preview/cancel never adds a recent item. These catalog preferences remain in memory and are separate from saved project content. Catalog colors are illustration choices; manufactured color availability is unknown.

None, one, multiple and whole-group selections have distinct inspector contexts. Multiple/group selection shows aggregate nominal body bounds, part-type count and selected colors rather than the no-selection overview. Body bounds exclude studs and presentation offsets. Individual parts show both instance identity and original definition identity. All copies from a multi-selection duplicate remain selected, enter Move together and undo together. A protected member blocks the whole duplicate.

## The building loop

Choosing a catalog part creates only a ghost and activates interactive 3D at every width. The first supported part starts **On the floor**, using the Grid policy with footprint-aligned one-stud horizontal and 0.4-stud vertical spacing. Further supported parts start **Attach to model**, using Connect. The initial preview tries a valid existing-core candidate above the active visible eligible selection, then the latest visible eligible support, then bounded candidates near the default floor position. Scope, focus and visibility restrict suggested targets; the full canonical model, including hidden pieces, still participates in collision checks. A valid suggestion changes neither counts nor history until **Place brick** or an explicit viewport placement commits it. If no candidate passes the ordinary Connect rules and workspace bounds, the preview retains its default transform and Connect policy for manual adjustment; it does not silently become Free or claim validity.

Unsupported visual details start in explicitly unverified Free position. The main controls expose **Attach to model** and **On the floor**, plus color, rotation and placement. Numeric fields and Grid/Connect/Free policy details are collapsed under **Advanced placement**. Connect target names and spatial positions remain available in **Choose a surface from the list**, with source sockets, stable identifiers and orientation options further disclosed. Catalog capability labels and the Connectable parts only filter follow the same supported geometry contract as placement. The candidate search uses the bounded world-distance heuristic documented in [modeling](MODELING.md), not a complete magnetic solver.

**Rotate** on a pending piece, including its R shortcut, changes only the preview. On the floor, the turned footprint remains aligned to the grid. Attach rotation retains the original height and searches around the nearby eligible support; it does not move the preview to a higher layer or an unrelated distant piece. Successive turns use one positional origin until the user changes position, so four turns return to the original preview rather than accumulating offsets. Free position keeps the center unchanged. If the intended connection cannot be retained legally, the preview remains blocked and the ordinary placement feedback explains why. Switching from **On the floor** back to **Attach to model** proposes a nearby valid connection when available, preserving the selected color and turn. Neither action places the piece; **Place brick** or an explicit viewport placement remains required. The [preview-intent contract](MODELING.md#placement-intent-and-preview-recovery) owns the bounded suggestion details.

Numeric placement values are a draft until **Update preview**. Escape inside a placement field restores its displayed preview coordinate while preserving the ghost; Escape from the workspace cancels that ghost. Place remains disabled while those values differ from the displayed ghost, so diagnostics and committed coordinates describe the same preview. Preview and commit share finite-value, bounds and precision validation: X/Z steps of 0.1 stud and Y steps of 0.05. Inline feedback explains invalid values before submission, without a separate native form-validation path. The fields describe body-center coordinates and show bottom/top heights. Place commits once and ends the preview unless Repeat placement is checked. Repeat hides the committed ghost and waits for a changed transform; the unchanged position cannot commit another copy or produce a stale conflict message. Escape or Cancel discards the preview without a count/history entry; losing focus or hiding the page also cancels transient placement. A camera gesture does not place a part. Ordinary accepted placement is announced through local status text rather than a success toast for every pointer movement.

Single selection, Shift-click membership and visible Multi-select share stable instance IDs with Structure and the inspector. The explicit whole-group toggle selects a group's descendants. Enter group establishes a visible editing scope; Exit group clears it. Missing scopes after undo/reset are ignored. Groups may be renamed or nested without changing their IDs or world transforms. Protected ancestors remain authoritative even when an individual descendant appears unlocked.

For one placed piece, **Move** or **Rotate** opens **Reposition piece** using the shared placement preview. Move/G can select an existing piece and preview a destination; Rotate/R starts the same flow with a quarter turn. The original instance remains canonical while its old rendered position yields to the ghost. Its count, identity, definition, color and group are unchanged until **Apply move**, an explicit viewport placement or Enter from the focused workspace applies one relocation command. **Cancel move** and Escape discard the preview without history. Color is read-only and Repeat is unavailable during relocation.

An already valid supported connection starts in Attach. A supported piece resting on the floor starts On the floor; a detached supported piece above the floor starts in Attach with its missing connection visible until repaired. Unsupported geometry starts in explicitly unverified Free position. Relocation reuses the pending rotation/recovery controls above. It excludes only the source piece from destination checks; hidden obstacles remain physical. Stale and protected edits fail without changing the model. Moving a support alone does not move its dependants or establish that the remaining model is supported.

Rigid multi-selection/group movement retains a pointer preview and one draft command at completion. Release outside the viewport, pointer cancellation, blur, hidden page and renderer loss discard that transient drag. Advanced numeric XYZ fields, axis increment buttons and bulk translation remain explicit free-form alternatives. Rotation is bounded to quarter turns about Y; multi-selection exposes active-part or selection-center pivot. Bulk translation can use world or the active part's local axes. Scaling, reflection and unconstrained three-axis rotations are not implemented.

Undo and Redo clear prior placement or duplication notices before announcing the actual history result. A changed count must not remain accompanied by a stale successful-action message. Advanced model transforms and duplication retain explicit free-form draft behavior; the primary single-piece relocation path has its own stated placement policy.

| P                                   | Open the parts panel in Build.                                                                                                                                      |

| F in the viewport                   | Fit selected parts, or fit the visible model when none is selected.                                                                                                 |
| Arrow keys in editor workspace      | Nudge a pending placement by one stud horizontally, or start that preview for one selected piece. Multi-selection/group drafts use 0.5 stud, or one with Shift.     |
| Enter in editor workspace           | Apply the current repositioning preview when valid. Text fields and native controls keep their own input behavior.                                                  |
| Page Up / Page Down                 | Translate the selection vertically by 0.4 stud as a free draft when no placement preview is active.                                                                 |
| Mod+D / Shift D                     | Duplicate the complete selected set in one command, select new identities and activate Move.                                                                        |
| Delete / Backspace                  | Submit removal of the selected set. Protection can reject the entire command.                                                                                       |
| Mod+Z / Mod+Shift+Z                 | Undo / redo within editable Build.                                                                                                                                  |
| Escape                              | Cancel the active viewport preview/export/candidate list or placement; restore a focus view when applicable. Numeric property fields restore their previous values. |

Shortcuts are scoped to the mounted editor or focused viewport, skip text/editable controls, and respect modal ownership. Some native controls retain their own arrow-key behavior. A visible Shortcuts dialog and Camera buttons menu explain the available alternatives. A secondary click opens contextual commands in the existing modal primitive. A completed secondary drag suppresses that menu.

Structure uses buttons, disclosure states, labels and a searchable list rather than claiming the ARIA tree keyboard pattern. Large groups show the first 150 matching parts and explain that exact-ID search reaches other instances. The inspector also offers a complete HTML part selector. Canvas interaction is accompanied by accessible naming and the same HTML document representation; it is not represented as thousands of unlabeled accessibility nodes. Local commit/error/cancel status uses a live region. Radix owns modal focus trapping and restoration; browser checks must still verify actual focus paths.

Implemented controls generally use 40px minimum height, enlarged to 44px for coarse pointers. Reduced-motion CSS shortens decorative transitions. These design choices do not certify WCAG conformance. Contrast, zoom/reflow, screen-reader behavior, real touch devices and pointer interruption scenarios require the evidence listed in [evidence](EVIDENCE.md).

Compact panels have a Close panel control and restore their toggle focus on close or completed non-repeat placement. Escape closes an idle compact panel; active placement retains cancellation priority. Desktop windows at least 740px tall use available `dvh` below the header. Shorter desktop windows keep a 35rem workbench area with independently scrolling panels and page scrolling; catalog length must not stretch the canvas. Focus canvas collapses both side panels and the shared header/navigation area. Panel widths can be set between 240 and 360px with native keyboard-operable selects in Local project files → Panel widths. No custom drag-resize engine is introduced. The roughly 55% canvas-width target is a design target, not a measured guarantee for every viewport. Narrow-screen rendering, reflow and device coverage must be recorded separately.

The document strip exposes Download project and the local save status. **Saved in this browser** appears only after the storage transaction completes; pending writes, storage failures and conflicting writes from another tab have distinct feedback. Local saving retains model geometry, edited instructions, brief, reference image bytes and declared scales across reload. Explicit backups include this project content but omit undo history and camera positions. A browser download request is labeled as requested; the browser cannot confirm that the file was retained. Browser storage belongs to the current browser and address and can be cleared, so it does not replace an external backup. The [local-project contract](../engineering/LOCAL_PROJECTS.md) owns restoration, write ordering and failure recovery.

## Inspection, changes and local artifacts

Focus lens temporarily isolates selected/affected IDs, including a deliberately hidden selected obstacle. User-hidden IDs remain a separate layer and return when the lens is restored. Hide selection never deletes physical membership or changes quantities. Checks include hidden instances, report supported conflicts and individually inspectable unchecked geometry, and become stale when revision changes. Results survive switching inspector tabs and are cleared on document replacement/reset. Clicking a current result selects its affected IDs, restores assembled rendering, exits an incompatible group scope and explicitly frames the focus lens. Stale result buttons remain disabled until recalculation; viewing a result never changes canonical coordinates or hidden physical membership. The inspection inspector remains read-only; return to assembled Build before repairing the selected part through a command.

Visual sectioning uses one axis and numeric offset without solid caps or Boolean geometry. Explicit select-through lists rendered surface hits by depth and applies the clipping policy; it does not search all user-hidden geometry. To reach an intentionally hidden part, use Structure and Focus lens. **Disassemble** opens the topmost current model layer on its own, including locally added pieces. **Previous layer**, **Current layer** and **Next layer** navigate these sections; Next moves downward. The camera fits the displayed section. **Show all layers** retains the complete separated overview, and **One layer at a time** returns to the focused section. **Lift the roof** is a separate metadata-dependent action; authored assembly separation remains an optional method. The slider and numeric amount change display offsets only. **Reassemble**, or **Assemble** in the toolbar, restores the assembled view and prior hide/focus choices without changing coordinates, count, revision or history.

The Changes rail executes a selected recolor, translate or remove command on a specific model revision. Current/Proposed/Highlight changes share one canvas. The rail lists exact affected IDs, counts, touched groups and stale-check implications. Changed remaining instances use selection accents in Highlight changes; removed IDs remain labeled in the impact list rather than appearing as extra physical parts. Accept is one transaction after stale/protection validation. Showing Current lets the user perform another edit while retaining the proposal, so stale behavior can be inspected. Closing the rail discards its transient preview.

Same-footprint replacement preserves instance identity, color and body-bottom position. The UI states connector changes or unknown coverage and does not infer surrounding fit from matching dimensions. Protected replacement is disabled with an explanation; an unknown connector alternative requires an explicit unverified-draft acknowledgment before replacement. Local reference images are pinned beside the model, limited to PNG/JPEG/WebP, six files, 10 MiB each and 40 million decoded pixels. Manual reference scale records two pixel anchors, a declared stud length and alignment. It does not place a calibrated image into the 3D scene; textured reference planes and image reconstruction are not implemented. Project-owned references survive panel and route changes, and validated bytes/scales are included in local saves and backups. Object URLs are temporary display resources, recreated from retained bytes and released by the project-context owner. PDF references retain filenames and metadata only.

Curated steps refer to stable IDs and one model revision. Current additions are visible with previous pieces muted; a changed model makes the plan stale. Restore view resets step activation. Restore step view explicitly returns to the shared authored isometric framing. Separately authored cameras are not implemented. Local generation from any current model is specified below.

Present offers actual square PNG output at 1024 or 2048 pixels, with an optional transparent background, using the current camera and complete assembled model. It excludes technical overlays and temporary hide/focus/section/step choices. A render-target operation restores renderer resources/settings afterward; browser evidence must establish resulting pixels and failure recovery. Neutral studio, Warm tabletop and Transparent background presets change presentation only. Arbitrary aspect-ratio export and inspection-view export are not implemented. Auto is a conservative fixed rendering profile rather than measured adaptive quality control. Performance and Quality are explicit visual profiles and never change domain diagnostics.

Project backups explicitly download/load the versioned model, instruction document and project context. The picker rejects empty files and files larger than 96 MiB before reading; model data retains its separate core limit. Legacy geometry-only scene files remain readable. The UI validates the entire file before replacement and asks before discarding current work; if the model changes while a read is pending, replacement also requires confirmation. Closing the file panel cancels a pending read's ability to replace the document. Restored files start fresh model and instruction undo histories. Renderer resources and arbitrary external CAD formats are excluded. Cloud sync, participant telemetry and a verified revolute-joint pose study are not implemented. [Local projects](../engineering/LOCAL_PROJECTS.md) defines package contents, validation and browser-storage boundaries.

## EDR-030 usability protocol

Status: protocol specified; **zero participants recruited, zero sessions conducted and no participant outcomes collected**. No claim of better usability or competitor superiority is supported. Recruitment or contacting participants requires a separate authorized activity; no messages were sent as part of this implementation.

Recruit 5–8 adult volunteers for a formative pilot, roughly balanced between people new to digital brick/CAD tools and experienced builders. Include keyboard-reliant interaction and touch review where actual participants/devices are available. Record familiarity and input preference rather than assuming ability from age or hardware. Obtain consent for the proposed notes/recording and store deidentified observations locally. A small convenience sample cannot establish population-wide completion rates.

Use a fresh local scene for each task, one fixed commit/catalog version, a recorded browser/OS/device, viewport, DPR, actual input method and quality. Record the actual fixture revision/count; the facilitator must verify that the named IDs and geometry exist. Start timing when the participant receives the task and stop on demonstrated completion. Give the same brief orientation to visible controls, then do not coach unless assistance is requested; record every intervention. A ten-minute per-task cap is a proposed pilot parameter, not a performance requirement. Stop early at the participant's request.

| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| U1 First-time builder | Open Empty scene; choose Brick 2 × 2 and Place brick; choose a second basic brick and place its attached preview without opening numeric controls. Participant can explain preview versus commit.        | Undo the second placement, retry, and demonstrate two canonical IDs with the expected count.                                                                                                                |
| U2 Precision builder  | Open Placement lab; choose Plate 1 × 3; select a source socket and a target; compare Keep orientation with Align to target; point to the reported rotation and coverage.                                 | Attempt the authored occupied region, explain the blocked result, then Cancel and verify original revision/count.                                                                                           |

| U4 Safe experiment    | Open Courtyard study, verify protected Facade, select Roof and preview a local recolor. | U5 Presentation       | Select a part; switch to Present; choose camera/projection/framing and request a 1024px PNG.                                                                                                             | Inspect the downloaded file's actual dimensions/content, return to Build, and verify original model revision/count and usable selection. A failed export is recorded as failure, not completion.            |

For every task record success without help, success with help, failure/timeout or participant stop; elapsed seconds; mistaken committed placements; blocked placement attempts; undo count; cancel count; help requests; and recovery time from the first mistake to the last valid state. Separately note wrong-ID selections, unexpected mode changes and misunderstood coverage labels. Capture before/after revision, count, selection IDs and a local artifact reference when permitted. Report medians/ranges and raw denominators, not precise general-population estimates. Missing observations remain missing.

Use two equivalent placement layouts and counterbalance their order across participants, balancing experience groups as far as the small sample allows. A causal simple-versus-explained-snapping comparison requires two prototype variants with the same kernel, candidates and task difficulty, changing only explanation exposure. That controlled variant is **not implemented**. Current Grid versus Connect changes the algorithm and is unsuitable for attributing differences solely to explanation. The initial pilot can evaluate explanation comprehension; a later A/B or B/A study can test retries/recovery once the matched variant exists. Report practice/order effects and avoid comparing competitors without actually running matched tasks.

## General-purpose workspace follow-up

The default entry remains individual pieces and an empty canvas, for any subject. Optional Building templates live in Project tools; they do not add an architecture tab, constrain free-form modeling or represent AI. Common camera, part, instruction and disassembly tools apply equally to vehicles, creatures, objects and buildings. The unconnected sample assistant sits inside the optional More tools section.

Primary editing tools float at the top of the editing area; a single named-view selector, Orbit, Fit, dimensions and zoom float below. Tool groups wrap within the available canvas. View tools contains optional rendering, projection, underside and select-through controls. Camera interaction has one shared input map, with no Mouse/Trackpad/Touch preset chooser. Project tools contains presentation/inspection modes, files and reset. The inspector opens on selection rather than consuming space for an empty selection. Placement feedback uses its own layout row; compact parts/inspector panels reserve space instead of covering the canvas.

Select picks a piece. Single-piece Move and Rotate use the Reposition piece preview and explicit Apply move; rigid multi-selection movement retains its draft drag behavior. Orbit is a separate navigation action and exiting it restores selection behavior. Native numeric fields under Advanced placement/Advanced position remain keyboard alternatives. Values and dimensions are shown in nominal centimeters, not raw model units. More filters and More colors keep the catalog compact; selected-part details retain the unsupported-geometry explanation.

### Local instruction drafts and disassembly

The Instructions route first offers **Generate instructions** from the current model, or opens its existing local draft. **Original sample instructions** is an explicit opt-in overview with its own baseline revision; it cannot stand in for the edited model. An empty model explains that pieces must be placed first.

Generation derives layers by body-bottom height from the actual current pieces, split into steps of at most eight additions. **3D view** and **Top view** are schematic SVG projections of those coordinates, saved independently for each step. **Focus this step** initially frames its additions; earlier geometry remains as context but can fall outside that framing. **Whole build** frames all pieces assembled by that step. Distant future additions affect neither frame. Earlier pieces are translucent and new pieces are drawn last in full color, making their positions visible through earlier geometry. The tray derives additions by part/color. These are nominal body/stud drawings with limited slope outlines, not exact catalog meshes or a verified insertion sequence. Long guides show ten step buttons at a time; **Browse steps** selects a range, while Previous/Next crosses those ranges normally.

**Edit step** saves its title and notes. **Arrange steps** exposes adjacent moves, **Merge with next step**, and **Split this step**. A split requires a nonempty strict subset of the current additions and places those pieces in a new following step. Merge preserves notes or explains the size limit; every operation retains each logical piece exactly once and recalculates cumulative visibility. These controls edit the guide, without moving model pieces or advancing its revision. **Undo instruction edit** and **Redo instruction edit** use a separate history of up to forty edits. Unchanged wording or an already selected view adds no history entry.

The source model snapshot, edited plan and editorial history persist during client navigation. Model changes mark the guide out of date; imports that reuse a revision but change geometry are also detected. A stale guide remains readable from its retained source snapshot, while its editing, saved-view and history controls are disabled. Restoring the source model re-enables them. Regeneration of an edited guide opens **Replace edited instructions?**, explaining that names, notes, saved views and sequence will be replaced. **Keep my steps** preserves them; **Replace with generated steps** creates a fresh current-model draft and clears editorial history. The original-sample entry uses the same confirmation, and the editor preview cannot silently overwrite an edited guide. This is explicit replacement, not automatic preservation or reconciliation of editorial changes after geometry edits.

Local saves and complete project backups retain the current instruction document and its source snapshot, including a stale guide. Model and editorial undo histories start fresh after reload or file restoration. Legacy scene JSON contains geometry only. Printing produces the current schematic step, not a production booklet. Named subassembly sequencing, custom camera poses, production booklet export and automatic reconciliation remain future work. The [local-project contract](../engineering/LOCAL_PROJECTS.md) owns compact serialization and restoration limits.

The editor step preview runs forward or in reverse, including a fully empty disassembly view without deleting any canonical parts. The separate **Disassemble** action defaults to one model layer at a time, as specified in [inspection](#inspection-changes-and-local-artifacts). These layers come from current body-bottom heights, not authored subassembly or physical insertion metadata. Authored roof/module views remain separate options for models that contain that metadata. Display offsets never change coordinates, revision or inventory. Neither height ordering, manual step edits nor contact diagnostics proves an accessible assembly sequence or physical stability. The [incremental UX review](../product/UX_REVIEW.md) tracks remaining user journeys and the [reference record](../references/README.md#september-25-product-and-competitor-conversations) distinguishes product direction from externally verified capability claims.
