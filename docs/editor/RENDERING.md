# Editor rendering contracts

Owner: frontend. Specialist pass: 1.0.0, 2026-09-24. Evidence status and recorded browser results belong to [evidence](EVIDENCE.md); pure contracts below are covered by [rendering tests](../../tests/unit/editor-rendering.test.ts). No manufacturer geometry or physical validation is implied.

The existing [client viewport](../../src/features/editor/components/model-viewport.tsx) lazily imports one [Fiber scene](../../src/features/editor/scene/model-scene.tsx), using `ssr: false` inside a Client Component. Three 0.186.0 requires WebGL 2. A renderer failure retains the canonical model and HTML tools; Retry remounts the renderer and regenerates owned GPU resources. Static previews are restricted to known authorized sample IDs. Stress and arbitrary imported models explicitly have no static poster.

## Coordinates and geometry

The inherited canonical convention is a right-handed Y-up frame measured in nominal stud pitches. X/Z are horizontal, positive quarter-turn rotation maps local positive X toward world negative Z. This pass retains that convention rather than converting persisted scenes to LDraw. One stud pitch corresponds nominally to 20 LDU; a brick body is 1.2 pitches, a plate 0.4, and studs 0.2 high. These proportions are not manufactured tolerance measurements. No LDraw assets are loaded or converted by this renderer.

Original procedural part bodies, open undersides, tubes, studs and openings remain owned by [part geometry](../../src/features/editor/scene/part-geometry.ts), [brick geometry](../../src/features/editor/scene/brick-geometry.ts) and their architectural/joinery helpers. Diagnostic metadata is independent and lives in the core. Rendering quality never changes domain geometry or diagnostics. Geometry tests exercise dimensional bounds and rays through actual cavity/opening surfaces; coarse bounding boxes are not final picks.

Each definition is rendered in an instanced body batch and an optional instanced stud batch. Muted parts use separate batches. A batch carries current stable part IDs and its instances-per-part mapping; instance slots are transient. Delete/repack reconstructs the mapping together with the matrices. Geometry/material meshes, studios, studs, reference images and overlays do not add canonical parts. An active placement ghost is the sole bounded exception to per-stud instancing, with at most the selected catalog part's stud count.

## Selection and presentation layers

Default picking uses the nearest rendered triangle surface and captured event coordinates. Fiber's root pointer-miss callback clears selection on an idle primary click through empty space, including elevation views where the ground plane is parallel to the ray. The same live interaction session rejects missed-click clearing during placement, dragging, Space-pan, export, select-through and rotation preview. Fiber limits this callback to click displacement of at most 2 CSS pixels. The [section raycast adapter](../../src/features/editor/scene/picking.ts) filters clipped intersections before Fiber deduplicates an instance's surfaces. Sectioning is a visual plane without solid caps. Select through lists distinct visible surface IDs in depth order; intentionally hidden parts remain available through Structure and the Focus lens. Transparent source-part materials are not part of the supported catalog subset.

Selection uses a colored bounding frame in addition to HTML identity. It preserves the part material; the frame is not a claim of a pixel-exact silhouette. Selection IDs can contain multiple parts, and the collection receives one translation preview. Focus isolates explicit IDs and temporarily reveals focused hidden instances, while retaining the original hidden-ID input. Leaving Focus restores that input. Step visibility and muted layers are presentation inputs. Assembly separation uses authored module offsets, never canonical coordinates. Rotation preview uses the active part as a rigid Y-axis pivot and commits only through the parent's validated command callback.

Inspect, section and exploded views notify `onEditingLockChange`, allowing the workbench to block all canonical mutation paths until assembled Build is restored. Canonical model transforms are not changed by camera, mode, section, focus, step or explosion actions.

## Camera and gesture ownership

One installed Drei OrbitControls instance owns navigation. Mouse uses secondary drag to orbit, middle drag or Space with primary drag to pan. A secondary pointer release without the 4px drag threshold opens contextual commands in the existing Radix Dialog; dragging suppresses that action. The native contextmenu event is prevented without opening a dialog, because some browsers emit it before the drag has finished. Trackpad mode permits primary-drag orbit; explicit touch navigation enables one-finger orbit and two-finger dolly/pan. Native Ctrl/Meta-wheel browser zoom is not prevented. Buttons provide pan, orbit, zoom, fit, focus and seven named views. Projection conversion retains the target plane's apparent vertical scale. Modes retain camera poses during the session and initially inherit the current pose. Projection preferences are stored per mode, with a new mode inheriting the current projection on first entry.

Below 640px, the workbench passes `compactControls` to keep optional controls in native View tools and Camera & view options disclosures. Both contain the same mounted controls used on desktop; the renderer is never duplicated. Select/Move/Rotate and active placement cancellation remain immediately reachable.

F fits selection (otherwise the visible model); V/G/R select tools. These handlers are scoped to the viewport and ignore inputs, textareas, selects and editable text. The camera remains available during placement. A move drag captures its pointer, starting revision and original transform. Its preview is calculated from that immutable start. Release inside commits once; no-op release commits nothing. Outside release, pointer cancellation, capture loss, blur, hiding the page or context loss discard the preview. Competing camera control is disabled during the captured model drag. A changed model revision rejects the drag commit. Mouse/touch movement thresholds are 4/8 CSS pixels.

The selected workplane determines translation axes and the grid's visible plane. Grazing orthographic views switch to isometric for manipulation; named compatible views remain available. World transforms and the canonical scale do not change when choosing a workplane.

## Color, quality and lifecycle

Catalog hex colors enter Three's managed linear working space via `Color`; output uses the renderer's sRGB path. Per-ID color variation was removed so identities retain their declared color. Normal Build uses nonmetallic plastic and readable seams. UI background/grid/selection colors are read from the canvas's inherited semantic variables, preserving editor-scoped ivory/teal tokens without recoloring model parts. Screen colors are approximations of physical plastic.

Auto is a conservative fixed profile: DPR 1–1.5, direct render, modest shadows and shared environment. Performance uses DPR 1, simpler cosmetic geometry and no shadows/environment. Quality enables the existing GTAO/OutputPass composition and contact shadows. Auto is not an adaptive controller and does not claim automatic measured downgrade. The renderer uses demand frames, with OrbitControls invalidation while damping settles. Hidden documents skip render work. Quality changes do not affect identity, world transforms, connector metadata or occupied-volume checks.

Each live batch owns its body and stud geometry; effect cleanup disposes both. Fiber owns and disposes its mounted material instances. GTAO, output, composer and render targets follow the explicit existing cleanup path. Caches are bounded by active catalog-definition/muting batches rather than history. Geometry counts may change with quality/scene contents; performance evidence must establish an observed plateau, not assume it.

Actual canvas attributes expose frame count, latest draw calls/triangles, geometry/texture counts, canonical revision, logical and displayed part counts, and read-only camera position/quaternion/target/projection/zoom. These are local test instrumentation with no network telemetry and no scene-write access. `onMetrics` reports the first rendered frame of each revision; canvas attributes retain subsequent counters. Scene-ready becomes true only after a fitted frame, and resets on context failure.

## PNG export

Present provides Neutral studio, Warm tabletop and Transparent background presets, affecting only stage/background/light appearance. Catalog color IDs and model geometry stay unchanged. It offers real 1024/2048-square PNG downloads, with optional transparent background. The export renders the complete assembled canonical model with the current camera; user hiding, focus, step masking, explosion and sectioning are excluded. Technical helper objects are temporarily hidden. A cloned camera adapts its aspect for a square output, so users should leave framing space at the sides. Export uses a temporary render target bounded by the actual texture/renderbuffer limit, reads pixels, flips rows, and encodes a local canvas. No preserved drawing buffer or second WebGL context is used.

Camera fitting, projection changes, camera buttons and OrbitControls are frozen while the assembled export snapshot is displayed. The camera fit key is not advanced by that temporary view, so the prior orbit/target survives export and restoration. The target, background and helper visibility are restored in `finally`; the target is disposed. Cancellation prevents a pending encoding result from downloading, and failures expose an error without modifying the model. No cloud job or production render service is implied. The direct PNG render does not include Quality's screen-space GTAO, so the declared plastic colors/geometry/camera match while optional occlusion differs.

Remaining narrower gaps: no free-angle or axis-handle rotation gizmo (explicit quarter-turn preview is available); adaptive quality is not implemented; real-device touch and screen-reader behavior require recorded manual evidence. These limits must remain visible in requirement status rather than treated as completed acceptance tests.
